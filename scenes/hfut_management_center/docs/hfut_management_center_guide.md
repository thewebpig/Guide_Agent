## 2. 管理学院与管理科学与工程学科

### 2.1 学科基本情况

合肥工业大学管理科学与工程学科具有较长期的建设基础。

该学科强调管理理论、系统科学、信息技术、人工智能和工程实践的深度融合。

5. 物流与供应链管理

# 7. 真实性与安全规则

## 7.1 禁止伪造室内坐标

`scene.json` 中的 `x`、`y`、`distance` 如果没有来自真实BIM、CAD、激光测绘或现场测量，则只能视为**导览系统测试用仿真坐标**。

## 7.2 禁止推测办公室

如果教师办公室没有官方公开资料，应回答：

> 目前公开资料中没有可核实的具体房间号。

不能根据同系教师办公室、楼层规律、房间号顺序或历史非官方信息推测办公室。

## 7.3 办公室并不等于随时可访问

即使公开了1106、1108等办公室，也不能保证教师当前在办公室、访客可直接进入或办公地点永久不变。建议提示：

> 办公室位置来自公开教师主页，实际访问前建议提前联系老师，并以现场标识为准。

## 7.4 临时活动信息

学术报告厅的活动安排具有明显时效性。知识库可以回答某报告厅是什么地方、历史上举办过什么类型活动，但“今天第二报告厅有什么活动？”应调用最新通知、联网检索或实时活动数据，不能直接根据历史知识文档回答。

# 11. 数据维护规则

本知识库不是一次生成后永久不变。

高变化信息：教师办公室、教师职务、学院领导岗位、报告厅活动、房间用途、开放权限、联系方式。

变化较慢的信息：建筑基本参数、学科历史、教师主要研究方向、建筑总体定位。

建议维护周期：

- 教师办公室：每学期核验
- 学院领导职务：每学期核验
- 活动安排：实时查询
- 建筑基础信息：有重大调整时更新
- 研究方向：每年核验一次教师主页

# 14. Guide Agent整体知识链路

本知识库与 `scene.json` 配合后，应形成三类互补知识：

**空间知识** → 建筑、房间、报告厅、办公室、路径节点  
**人物与科研知识** → 教师、研究方向、学科、科研关系  
**行为规则** → 什么时候直接回答、什么时候RAG、什么时候调用路径规划、什么时候说明不确定

整体链路：

```text
用户问题
   ↓
意图识别
   ├── 知识问答 → RAG → 本知识文档
   ├── 地点查询 → scene.json
   ├── 路径规划 → scene.json + Dijkstra
   └── 混合问题 → RAG + scene.json + Tool
   ↓
LLM组织最终回答
```

目标是让“合肥工业大学管理学院智能导览Agent”同时具备**问答能力、实体理解能力、人员查询能力和可执行的路径规划能力**。
